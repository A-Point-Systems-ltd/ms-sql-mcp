# Changelog

## 1.0.0

- Extension display name is **APoint-ms-sql** (Extensions view, activity bar, command category, Output channel, Results panel). The extension id stays `apoint.ms-sql-mcp`, so settings and saved connections carry over.

- Named SQL Server connection profiles (Windows, SQL and Entra auth); SQL passwords are kept in VS Code SecretStorage only.
- Object explorer tree per connection with a read-only data view and DDL (`mssql-ddl:` documents) for tables, views, procedures, functions, triggers, types and security objects; object name filter.
- Explorer profiles are forced read-only, so the explorer can never modify data.
- Bundled MSSQL-MCP server (.NET 10, single file) exposed natively to VS Code agents via an MCP server definition provider.
- One-click registration with Cursor, Claude Desktop and Claude Code; existing config files are merged after a timestamped backup, and invalid JSON is never overwritten. Plain-text passwords for external clients require an explicit confirmation; `${env:NAME}` placeholders avoid them.
- Connection settings inherited from the editor's environment (`CONNECTION_STRING`, `MSSQL_CONNECTIONS_FILE`, `MSSQL_CONNECTIONS`) never add connections to the agent server, the explorer or registered clients.
- The agent server's definition version changes with every non-secret connection or setting change, so VS Code prompts to refresh a running server.
- Automatic `connections.json` refresh always applies close / remove / read-only; a new connection that needs a new `${env:}` variable is left out until re-registration (warning with Re-register), and the file is deleted when no connection is left.
- Commands are registered even when the editor has no MCP server definition API.
- Connection fields reject `${env:`; trace logging records only the row count of `read_data` results.
- Cursor: the agent server is registered with Cursor's own `cursor.mcp.registerServer` API (Cursor ignores VS Code's MCP server definition provider), so it appears in Cursor without any manual registration. A one-time warning flags an existing `ms-sql` entry in `~/.cursor/mcp.json`; the "Register with Cursor / Claude..." Cursor option is then only needed for the cursor-agent CLI.
- The extension-only `MSSQL_SCRIPT_RUNNER` switch is never inherited by the agent server or by servers registered with external clients.
- Add / Edit Connection is a single form (replacing the quick-pick wizard): all settings at once, inline per-field errors, **Test connection** and **List databases** on the unsaved values, and an existing saved password is kept when its field is left empty.
- Query windows: **New Query** on an open connection opens a SQL editor bound to it; a status bar item shows the bound connection (with a lock when read-only) and **Change Connection** rebinds it. Scripts run in a third private server process that keeps each connection's own read-only flag and is the only one with the extension-only `run_script` tool. Trace logging records only counts for `run_script` results.
- Query windows run with F5 or the editor title's Run button (the selection, or the whole document) and can be cancelled. Results and messages show in a bottom **MSSQL-MCP Results** panel; message lines link to the editor. Object documents on a read-only connection show a disabled Run button that explains why. New setting `msSqlMcp.query.maxRows` (default 1000). A connection change never kills a running query; `mssql-ddl:` views are never bound to a connection.
- Editable DDL: Show DDL on a view, stored procedure, table-valued function or scalar function opens an editable SQL file bound to its connection (`CREATE OR ALTER`, or `ALTER` on servers before 2016 SP1), saved under the extension's storage folder. Run / F5 applies it on a read/write connection; a read-only connection shows the disabled Run button with the reason. Unsaved edits are kept when the object is opened again. Other object types stay read-only.
- README: Features list, Query window, Editing views, procedures and functions, and a note that agents never get `run_script`.
- Wrong-target guard for editable DDL: an object file records the server and database it was scripted from. Run asks for confirmation ("This script was generated from ... but will run on ... Run anyway?") when its connection now points elsewhere or the file was rebound with Change Connection, which also says so when used.
- Split editors: Run, Cancel and the disabled read-only Run button in the editor title act on their own editor's document (per-document context keys `msSqlMcp.runnableDocs`, `msSqlMcp.blockedDocs`, `msSqlMcp.runningDocs`), not on the active editor.
- F5 runs SQL only outside a debug session (`!inDebugMode`).
- A CLR or encrypted module opens as the read-only document with its warning instead of a comment-only editable file, and "Applied to" is shown only when at least one batch ran without an error.
- The results grid shows exact `decimal` / `money` / large `bigint` values (sent as text by the server) right-aligned by column type, binary values as `0x…` hex, and marks values the server truncated (tooltip with the full size). README documents the server's per-run caps, the new session per run, and that Cancel or closing the tab does not undo work already committed.
- The duplicate `ms-sql` entry warning for `~/.cursor/mcp.json` shows on every start while the entry exists, until **Don't show again**.
- Source hygiene: literal NUL and BOM characters in the sources are written as `\u0000` / `\uFEFF` escapes, so git treats the files as text.
- Query windows and editable object scripts are `mssql-sql:` documents whose tab title shows where they run: exactly `<objectName> - <server> - <database>`, with no file extension and always in SQL mode (`Query N` for New Query, numbered per session and skipping open numbers; `<schema>.<name>` for object scripts; a raw connection string's `Data Source` / `Initial Catalog`, or `connection string` / `default`). They are kept in the extension's storage folder (`sqldocs/`), not as workspace files: Ctrl+S saves a query window's text. Closing it keeps any non-empty text (only an empty query window is deleted), and Save As makes a real file copy. Activation event `onFileSystem:mssql-sql` restores such tabs after a restart.
- The extension no longer edits editor text itself (no workspace edits): reopening a clean object script reloads it through the `mssql-sql:` file system, so Cursor shows no **Keep / Undo** review buttons for it.
- **Open Recent Query…** (command palette, and the history icon in the APoint-ms-sql view title) lists the kept query windows newest first (title, connection, relative time). It reopens one with its binding and the current title rules. A cleanup runs once, 15 seconds after startup: it deletes kept query windows closed more than 30 days ago (never one that is open) and empty orphaned query windows, and re-lists kept text that lost its entry as "Recovered query <id>". Object documents are never deleted automatically. Index or file read errors leave everything as it is. A damaged index is kept as `query-index.json.bad-<timestamp>` and rebuilt from the saved query windows; recovered entries start a fresh 30-day period.
- Migration: the bindings of the old `edits/` object script files are removed in that cleanup on the first start, and the folder is renamed to `edits.old-<yyyyMMddHHmmss>` (kept on disk); open the object again from the tree.
- DDL history: a new connection option **DDL history (audit trigger)** (off by default). After a save that turns it on, the extension checks the database for `dbo.DDL_AuditLog` and the `DDL_Audit` database trigger and, on a read/write connection, offers to create whatever is missing behind a modal confirmation that names the server and database. Existing ones are never changed; a disabled trigger, an incompatible existing table and read-only connections only get a warning, and the modal is offered only when the server reports that it can install. The option is not part of the agent server's configuration.
- **Show DDL History** (editor title of object documents and DDL views, and the tree's right-click menu of tables, views, procedures, functions, triggers and types on connections with the option): the recorded changes newest first, each opening a read-only `mssql-history:` diff against the previous recorded version; modules can also compare the newest non-DROP version with their current definition. Entries are filtered by object type, and an empty list explains a missing (with Set up…) or disabled trigger. History documents are keyed by the connection's server/database, so an edited connection never shows cached text. Per-document context key `msSqlMcp.historyDocs`; trace logging records only entry counts and command text lengths.
- DDL history install modal: names the server and database the server reports (`@@SERVERNAME` / `DB_NAME()` from `ddl_history status`, the connection's fields only as a fallback), and says that the trigger runs as dbo, never blocks a DDL statement if logging fails, and is removed with `DROP TRIGGER [DDL_Audit] ON DATABASE`. Saving an edit that points a connection with DDL history on at another server or database runs the set-up check again.
- Tab titles follow the connection: Change Connection on a query window, or an edit of its connection's server or database, saves it and reopens the same document under the new title (binding kept). A window with unsaved edits is renamed after its next save ("The tab title updates after you save."). Object scripts follow edits of their connection.
- Object scripts keep a base copy (`sqldocs/object/<id>.base.sql`, the last script loaded from the server or applied by a whole-document Run). Opening the object again from the tree when the saved text differs asks "You have saved, unapplied edits to <obj>. Replace them with the current server version?" (Replace / Keep my edits), so saved but unapplied edits are never silently overwritten.
- The legacy `edits/` folder is renamed to `edits.old-<yyyyMMddHHmmss>` instead of deleted (the path is logged at info).
- The DDL history diff of the oldest listed entry says "not loaded" whenever the server returned a full page, even when the type filter dropped some of it.
- Windows x64 only.
