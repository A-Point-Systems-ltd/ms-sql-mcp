# Changelog

## Unreleased

- **Format SQL**: right-click **Format Document / Format Selection / Format SQL** or **Ctrl+F2** (selection, else the document) formats T-SQL in the team style (ScriptDom parser; only whitespace and keyword case change, verified on every run). Settings `msSqlMcp.format.keywordCase`, `msSqlMcp.format.maxItemsPerRow`. Works without a connection: the runner process now starts without one.
- **Enhanced completions** (switch in the SQL editor tab's **...** menu and right-click menu; setting `msSqlMcp.completion.enhanced`): JOIN clauses and ON conditions from foreign keys or matching key names, generated table aliases, the **Pick columns…** checklist, `*` expansion (light bulb), and quick snippets with a **⇥ Tab** hint (`ssf` → `select top(100) * from`, and more).
- **Ctrl+3** Select Top Rows of the table / view under the cursor (Data View) or a table-valued function (new query with its parameters, not run). **Ctrl+F12** opens the object's script in a new tab. Both scoped to SQL editors bound to a connection.
- In SQL editors only, the new keys replace VS Code's **Change All Occurrences** (Ctrl+F2), **Focus Third Editor Group** (Ctrl+3) and **Go to Implementations** (Ctrl+F12); rebind them in Keyboard Shortcuts if you prefer the defaults.
- Format Document / format-on-save serve the extension's query windows only; `msSqlMcp.format.formatFiles` (off) opts `.sql` files and untitled editors in. A script that does not parse is reported in the status bar on save, not in a dialog.
- Failures of IntelliSense and Format SQL calls are logged without their message (it can quote the script).
- Object explorer: database roles, users, server roles and logins script with titled sections and their permissions, owned schemas and memberships (logins also with their user in the connection's database).
- Data View: double-clicking a cell that cannot be edited shows why (read-only connection, view, no primary key, identity / computed column, value too long) instead of opening the value in a new tab; the hover button still opens the viewer. Results grids are unchanged.
- Data View: `sql_variant` columns can be edited; values are saved as text (`N'...'`), so the stored base type becomes nvarchar.

- Marketplace / Open VSX icon: the A Point logo (`media/icon.png`, 512x512). No functional changes.

## 1.1.0

- The bundled server (1.1.0) returns TOON rows by default to agents; see the server changelog's BREAKING note. The extension's own views are unaffected (they ask for JSON).
- Connection form: **List databases** shows every database, labelling the ones that are not online (`Sales (offline)`), and works with an empty Database field and for raw connection strings (it lists through the typed database, falling back to `master` only when that database cannot be opened, so contained-database users can list). When the database is OFFLINE (from the list, a failed **Test connection**, or a check when saving a new connection) the form offers **Bring online**, confirmed in a modal dialog, which runs `ALTER DATABASE … SET ONLINE` through the probe process's new `probe_*` tools (`MSSQL_PROBE_TOOLS=true`, set for that process only and blanked for every agent-facing server). Saving a new connection to an OFFLINE database asks **Bring online & save** or **Save anyway**. **Test connection** uses the server's `probe_test`, which recognises an unavailable database by SQL error number, so the offline hint also works on servers with non-English messages (an older server exe falls back to matching the English text).
- The extension asks the server's TOON-capable tools (`read_data`, `list_objects`, `list_insights`, `get_insight_history`) for JSON on every call it makes (`toon=false`), so the explorer, Data View and history keep working with the server's new TOON default.

- **Register with Cursor / Claude...** now sets `MSSQL_MANAGED_CONNECTIONS_FILE=%APPDATA%\APoint-ms-sql\connections.json` on the Claude Desktop entry only, which turns on the server's connection manager form (MCP Apps) there. Cursor and Claude Code entries are unchanged. Re-register Claude Desktop to get it.

## 1.0.0

- SQL IntelliSense in editors bound to an open connection: completion (tables, views, columns, CTEs, variables, functions, procedure parameters, keywords), hover and signature help from the bundled server's `language_service` (Microsoft SqlParser). Completion opens on `.` space `(` `,` `@` `[`; typing-triggered requests wait 150 ms and are cancelled on the server as you type. The metadata cache is warmed when a window is bound (New Query, editable script, Change Connection) or a bound tab becomes active, at most once per connection every 5 minutes; until it is ready the list has keywords only and the status bar says so. New command **Refresh IntelliSense Cache** (editor title, editor context menu, palette, **Ctrl+Shift+R** in bound editors, which replaces VS Code's Refactor… there) and setting `msSqlMcp.intellisense.enabled` (default `true`). Other SQL extensions' providers stay active. Trace logs record only the document length and item counts.
- The VSIX ships `THIRD-PARTY-NOTICES.txt`: the bundled server includes Microsoft SqlParser (SMO License Terms) for its IntelliSense tool.

- Data grid features (Data View and Results): freeze columns (first column by default, **Freeze up to here** from a header's right-click), hide / show columns (**Columns** checklist), reorder by dragging headers, **Wrap** all rows, row **Stripes**, a filter row per column (`contains`, `=`, `starts with`, `is null`, `is not null`; server-side in Data View, local in Results), quick **Search** with match count and previous / next, cell selection with Ctrl+A / Ctrl+C and count / sum / min / max / avg (exact decimals), **Copy row** (tab-separated or JSON), an **Open in viewer** read-only tab per cell (pretty JSON, indented XML), and **Export CSV** (UTF-8 with BOM, RFC 4180, formula neutralization of text values with `'`, setting `msSqlMcp.export.neutralizeFormulas`) behind a modal confirmation every time. A failed sort / filter / reload keeps the loaded rows with the parameters they were queried with, and Load more pages only with those. Data View adds **Load more** (ROW_NUMBER paging over the sort column and the primary key, up to 10000 rows). The column layout survives reload, sort, filter and load more of the same Data View.
- Data grid for Data View and the Results panel (one shared implementation): rows are one line of text (full value, up to 2000 characters, in the tooltip); drag a header edge to resize a column (min 40 px) and double-click it to auto-fit (up to 600 px); a row-number gutter whose bottom edge resizes the row, and a double-click fits the row to its content (wrapped, up to 400 px) or returns it to one line; a hover copy button per cell copies that value (NULL as empty, binary as `0x…`, full text) and shows "Copied" in the status bar; header clicks sort ascending / descending / none.
- Data View runs `SELECT TOP (n) * FROM [schema].[name]` through the runner's `run_script` (column names and types even for 0 rows, exact value encodings), with a **TOP** box and **Reload** (Enter too) and server-side sort (`ORDER BY` the bracket-quoted column; types that cannot be ordered are not sortable). The panel keeps its object, TOP and sort until reused, and shows errors inline; a sort whose column is gone after a reload is cleared with "Sort column no longer exists". It is one fixed generated SELECT, run under the profile's own read-only flag. Copy says "Copied (value truncated by the server)" for a server-truncated value, and ignores clicks from an outdated page. `msSqlMcp.dataViewRows` now defaults to 200.
- The Results panel sorts each result set locally over the loaded rows (stable, NULLs first, numbers by value), with a "sorted locally (loaded rows only)" caption.
- Fully renamed to **APoint-ms-sql**: the MCP server key (Cursor, the VS Code provider, `~/.cursor/mcp.json`, Claude Desktop, Claude Code) is `APoint-ms-sql` (Cursor lists it as `extension-APoint-ms-sql`; the prefix is Cursor's), and every notification, tooltip, modal and the "Generated by" line of DDL documents says APoint-ms-sql. Registering with external clients removes the legacy `ms-sql` key (after the timestamped `.bak`), and the duplicate-entry warning also fires for it.
- Tab titles keep the server part of `server\instance`: Cursor shows only what follows a backslash in a tab label, so in the tab title (not in the status bar, tooltips or dialogs) the backslash is shown as the look-alike `∖` (U+2216), e.g. `Query 1 - dc∖dev16 - EasyHouse`.
- Extension display name is **APoint-ms-sql** (Extensions view, activity bar, command category, Output channel, Results panel). The extension id stays `apoint.ms-sql-mcp`, so settings and saved connections carry over.

- Named SQL Server connection profiles (Windows, SQL and Entra auth); SQL passwords are kept in VS Code SecretStorage only.
- Object explorer tree per connection with a read-only data view and DDL (`mssql-ddl:` documents) for tables, views, procedures, functions, triggers, types and security objects; object name filter.
- The object tree and DDL use a private explorer process whose profiles are forced read-only, so they can never modify data. Data View runs its generated SELECT through the query runner under the profile's own read-only flag.
- Bundled APoint-ms-sql server (.NET 10, single file) exposed natively to VS Code agents via an MCP server definition provider.
- One-click registration with Cursor, Claude Desktop and Claude Code; existing config files are merged after a timestamped backup, and invalid JSON is never overwritten. Plain-text passwords for external clients require an explicit confirmation; `${env:NAME}` placeholders avoid them.
- Connection settings inherited from the editor's environment (`CONNECTION_STRING`, `MSSQL_CONNECTIONS_FILE`, `MSSQL_CONNECTIONS`) never add connections to the agent server, the explorer or registered clients.
- The agent server's definition version changes with every non-secret connection or setting change, so VS Code prompts to refresh a running server.
- Automatic `connections.json` refresh always applies close / remove / read-only; a new connection that needs a new `${env:}` variable is left out until re-registration (warning with Re-register), and the file is deleted when no connection is left.
- Commands are registered even when the editor has no MCP server definition API.
- Connection fields reject `${env:`; trace logging records only the row count of `read_data` results.
- Cursor: the agent server is registered with Cursor's own `cursor.mcp.registerServer` API (Cursor ignores VS Code's MCP server definition provider), so it appears in Cursor without any manual registration. A one-time warning flags an existing `ms-sql` entry in `~/.cursor/mcp.json`; the "Register with Cursor / Claude..." Cursor option is then only needed for the cursor-agent CLI.
- The extension-only `MSSQL_SCRIPT_RUNNER` switch is never inherited by the agent server or by servers registered with external clients.
- Add / Edit Connection is a single form (replacing the quick-pick wizard): all settings at once, inline per-field errors, **Test connection** and **List databases** on the unsaved values, and an existing saved password is kept when its field is left empty.
- Query windows: **New Query** on an open connection opens a SQL editor bound to it; a status bar item shows the bound connection (with a lock when read-only) and **Change Connection** rebinds it. Scripts run in a third private server process that keeps each connection's own read-only flag and is the only one with the extension-only `run_script` tool. Trace logging records only counts for `run_script` results.
- Query windows run with F5 or the editor title's Run button (the selection, or the whole document) and can be cancelled. Results and messages show in a bottom **APoint-ms-sql Results** panel; message lines link to the editor. Object documents on a read-only connection show a disabled Run button that explains why. New setting `msSqlMcp.query.maxRows` (default 1000). A connection change never kills a running query; `mssql-ddl:` views are never bound to a connection.
- Editable DDL: Show DDL on a view, stored procedure, table-valued function or scalar function opens an editable SQL file bound to its connection (`CREATE OR ALTER`, or `ALTER` on servers before 2016 SP1), saved under the extension's storage folder. Run / F5 applies it on a read/write connection; a read-only connection shows the disabled Run button with the reason. Unsaved edits are kept when the object is opened again. Other object types stay read-only.
- README: Features list, Query window, Editing views, procedures and functions, and a note that agents never get `run_script`.
- Wrong-target guard for editable DDL: an object file records the server and database it was scripted from. Run asks for confirmation ("This script was generated from ... but will run on ... Run anyway?") when its connection now points elsewhere or the file was rebound with Change Connection, which also says so when used.
- Split editors: Run, Cancel and the disabled read-only Run button in the editor title act on their own editor's document (per-document context keys `msSqlMcp.runnableDocs`, `msSqlMcp.blockedDocs`, `msSqlMcp.runningDocs`), not on the active editor.
- F5 runs SQL only outside a debug session (`!inDebugMode`).
- A CLR or encrypted module opens as the read-only document with its warning instead of a comment-only editable file, and "Applied to" is shown only when at least one batch ran without an error.
- The results grid shows exact `decimal` / `money` / large `bigint` values (sent as text by the server) right-aligned by column type, binary values as `0x…` hex, and marks values the server truncated (tooltip with the full size). README documents the server's per-run caps, the new session per run, and that Cancel or closing the tab does not undo work already committed.
- The duplicate `ms-sql` entry warning for `~/.cursor/mcp.json` shows on every start while the entry exists, until **Don't show again**.
- Source hygiene: literal NUL and BOM characters in the sources are written as `\u0000` / `\uFEFF` escapes, so git treats the files as text.
- Query windows and editable object scripts are `mssql-sql:` documents whose tab title shows where they run: exactly `<objectName> - <server> - <database>`, with no file extension and always in SQL mode (`Query N` for New Query, numbered per session and skipping open numbers; `<schema>.<name>` for object scripts; a raw connection string's `Data Source` / `Initial Catalog`, or `connection string` / `default`). They are kept in the extension's storage folder (`sqldocs/`), not as workspace files: Ctrl+S saves a query window's text. Closing it keeps any non-empty text (only an empty query window is deleted), and Save As makes a real file copy. Activation event `onFileSystem:mssql-sql` restores such tabs after a restart.
- The extension no longer edits editor text itself (no workspace edits): reopening a clean object script reloads it through the `mssql-sql:` file system, so Cursor shows no **Keep / Undo** review buttons for it.
- **Open Recent Query…** (command palette, and the history icon in the APoint-ms-sql view title) lists the kept query windows newest first (title, connection, relative time). It reopens one with its binding and the current title rules. A cleanup runs once, 15 seconds after startup: it deletes kept query windows closed more than 30 days ago (never one that is open) and empty orphaned query windows, and re-lists kept text that lost its entry as "Recovered query <id>". Object documents are never deleted automatically. Index or file read errors leave everything as it is. A damaged index is kept as `query-index.json.bad-<timestamp>` and rebuilt from the saved query windows; recovered entries start a fresh 30-day period.
- Migration: the bindings of the old `edits/` object script files are removed in that cleanup on the first start, and the folder is renamed to `edits.old-<yyyyMMddHHmmss>` (kept on disk); open the object again from the tree.
- DDL history: a new connection option **DDL history (audit trigger)** (off by default). After a save that turns it on, the extension checks the database for `dbo.DDL_AuditLog` and the `DDL_Audit` database trigger and, on a read/write connection, offers to create whatever is missing behind a modal confirmation that names the server and database. Existing ones are never changed; a disabled trigger, an incompatible existing table and read-only connections only get a warning, and the modal is offered only when the server reports that it can install. The option is not part of the agent server's configuration.
- **Show DDL History** (editor title of object documents and DDL views, and the tree's right-click menu of tables, views, procedures, functions, triggers and types on connections with the option): the recorded changes newest first, each opening a read-only `mssql-history:` diff against the previous recorded version; modules can also compare the newest non-DROP version with their current definition. Entries are filtered by object type, and an empty list explains a missing (with Set up…) or disabled trigger. History documents are keyed by the connection's server/database, so an edited connection never shows cached text. Per-document context key `msSqlMcp.historyDocs`; trace logging records only entry counts and command text lengths.
- DDL history install modal: names the server and database the server reports (`@@SERVERNAME` / `DB_NAME()` from `ddl_history status`, the connection's fields only as a fallback), and says that the trigger runs as the low-privilege loginless user `DDL_Audit_Writer` (INSERT/SELECT on `dbo.DDL_AuditLog` only), that a failed log write lets the DDL run unlogged except when another trigger on `DDL_AuditLog` rolls back, and that it is removed with `DROP TRIGGER [DDL_Audit] ON DATABASE; DROP USER [DDL_Audit_Writer]`. When the table already exists it also says that the install grants INSERT and SELECT on it to `DDL_Audit_Writer`. The server's `status.warnings` (for example a lossy `varchar(max)` `CommandText`) are added to the dialog, or shown as an information message when no dialog is needed. History entry ids are read as bigint-safe numbers (number or digit string). Saving an edit that points a connection with DDL history on at another server or database runs the set-up check again.
- Tab titles follow the connection: Change Connection on a query window, or an edit of its connection's server or database, saves it and reopens the same document under the new title (binding kept). A window with unsaved edits is renamed after its next save ("The tab title updates after you save."), or after a run in it ends. Object scripts follow edits of their connection.
- Object scripts keep a base copy (`sqldocs/object/<id>.base.sql`, the last script loaded from the server or applied by a whole-document Run without errors). Opening the object again from the tree when the saved text differs asks "You have saved, unapplied edits to <obj>. Replace them with the current server version?" (Replace / Keep my edits), so saved but unapplied edits are never silently overwritten.
- DDL history set-up: when the server reports that it cannot install on a read/write connection and says why (for example an existing `DDL_Audit_Writer` with more rights than it needs), that warning is shown instead of the dialog. `loggingSuppressed` (DML triggers on `dbo.DDL_AuditLog`) is shown as "dbo.DDL_AuditLog has triggers, so DDL_Audit does not record changes." in the set-up check and for an empty history list. A tab retitled right after a run keeps its Results and Messages.
- The legacy `edits/` folder is renamed to `edits.old-<yyyyMMddHHmmss>` instead of deleted (the path is logged at info).
- The DDL history diff of the oldest listed entry says "not loaded" whenever the server returned a full page, even when the type filter dropped some of it.
- Windows x64 only.
